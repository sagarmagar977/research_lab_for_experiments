# I would split it into two files.

## 1. Experiment Metadata (JSON)

This stores everything needed to reproduce the experiment.

Example:

```json
{
  "experiment_id": "exp_00021",
  "frame_a": "frame_0062.jpg",
  "frame_b": "frame_0063.jpg",
  "created_at": "2026-08-07T00:01:00",

  "software": {
    "feature_lab_version": "2.0.0",
    "opencv": "4.11.0"
  },

  "configuration": {
    "hist_bins": 32,
    "hist_grid_size": 2,
    "color_mode": "RGB",
    "hist_epsilon": 1e-10,
    "canny_low": 50,
    "canny_high": 150,
    "ssim_window": 11,
    "text_threshold": 127
  }
}
```

This file is **never used for training**.

Its purpose is

* reproducibility
* debugging
* research documentation
* thesis appendix

Example

| frame_a_brightness | frame_b_brightness | frame_a_entropy | frame_b_entropy | pair_rgb_corr | pair_rgb_bhat | pair_ssim | label |
| ------------------ | ------------------ | --------------- | --------------- | ------------- | ------------- | --------- | ----- |

No JSON.

No config.

No version.

No timestamps.

No image names.

Only

```text
X
```

(features)

and

```text
y
```

(label)

## feature_manifest.json

This becomes extremely useful later.

Example

```json
{
  "frame_a_brightness": {
    "type": "float",
    "group": "brightness",
    "description": "Mean brightness of Frame A"
  },

  "pair_rgb_corr": {
    "type": "float",
    "group": "histogram",
    "description": "RGB histogram correlation"
  },

  "pair_gray_bhat": {
    "type": "float",
    "group": "histogram",
    "description": "Gray histogram Bhattacharyya distance"
  }
}
```

Later when XGBoost says

```
pair_gray_bhat
importance = 0.27
```

you immediately know what it means.

# One thing I would **not** remove

I would **keep the image names somewhere**, but not in the ML dataset.

For example:

```json
{
    "sample_id": 1456,
    "frame_a": "frame_0062.jpg",
    "frame_b": "frame_0063.jpg",
    "dataset_row": 1456
}
```

This lets you trace any suspicious prediction back to the original image pair during debugging.

## My recommended structure

```
dataset/

├── metadata/
│   ├── experiment_001.json
│   ├── experiment_002.json
│   └── ...
│
├── datasets/
│   ├── candidate_frame_dataset.csv      ← used for training
│   └── candidate_frame_dataset_test.csv
│
├── feature_manifest.json                ← explains every feature
│
└── labels.csv                           ← optional if labels are stored separately
```

I think this organization is much cleaner for a research project. It separates **experiment reproducibility** (metadata) from **machine learning data** (features), keeps the training dataset focused, and makes the pipeline easier to maintain and debug as it grows.
