## One suggestion to improve the plan

I would **not** expand to 98 columns just because you can. The criterion should be: **does this feature represent meaningful information, or is it just another statistic?**

For example:

* ✓ Brightness
* ✓ Contrast
* ✓ Entropy
* ✓ Edge density
* ✓ Text occupancy
* ✓ Histogram statistics
* ✓ Grid statistics
* ✓ Pairwise metrics

are all defensible.

But adding statistics simply because every vector can produce a mean, max, min, variance, and standard deviation can lead to redundant features. Since tree-based models (Random Forest, XGBoost, LightGBM) can report feature importance later, it's often better to start with a comprehensive but justifiable set, then remove consistently uninformative features after training rather than inventing more statistics upfront.

Overall, though, the architecture you're moving toward is the one used in many vision pipelines:

**Images → Individual Features → Pairwise Features → One Combined Dataset → Train Classifier → Feature Importance → Hyperparameter Tuning → Final Candidate Selection Model.**

That progression is coherent and sets you up well for the next stages of your research.
