This is a good implementation plan. I would proceed with it with **one modification**.

### What I like

It fixes the actual issue instead of hiding it.

* ✅ L1 normalization (instead of MINMAX) is the correct preprocessing for histogram comparison.
* ✅ Epsilon avoids divide-by-zero for Chi-Square.
* ✅ Assertions catch bad histograms immediately instead of silently producing garbage.
* ✅ Tests include identical, blank, brightness-shifted and different images.
* ✅ Stores all four histogram metrics instead of forcing one.

Those are all worthwhile improvements.

---

## One thing I would change

I would **not** hardcode `1e-10`.

Instead make it configurable.

```python
@dataclass
class PairwiseFeatureConfig:
    ...
    histogram_epsilon: float = 1e-10
```

Then

```python
hist += config.histogram_epsilon
hist /= hist.sum()
```

Reason:

If you later experiment with

* 0
* 1e-12
* 1e-10
* 1e-8

you won't touch the code.

Everything stays reproducible.

# I would also add one assertion

Instead of only

```python
assert abs(hist.sum()-1.0)<1e-5
```

also add

```python
assert (hist >= 0).all()
```

because histogram bins should never become negative.

# One more thing I'd verify

For every metric, make sure the direction is documented.

For example

| Feature       | Similarity? | Better |
| ------------- | ----------- | ------ |
| Correlation   | similarity  | higher |
| Intersection  | similarity  | higher |
| Bhattacharyya | distance    | lower  |
| Chi-Square    | distance    | lower  |
| SSIM          | similarity  | higher |
| MAD           | distance    | lower  |

Otherwise six months later you'll forget which direction means "more similar."

---

# One thing I would NOT do

Don't normalize these four outputs before storing them.

Store

```
Correlation = 0.92

Intersection = 0.81

Bhattacharyya = 0.18

ChiSquare = 2.91
```

exactly as they are.

The ML model can learn from raw values.

Scaling (StandardScaler/MinMaxScaler) belongs in the training pipeline, **not** in feature extraction.
